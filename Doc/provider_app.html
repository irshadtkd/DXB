📝 DRAFT
Registration in progress. Limited access — can fill profile, upload docs. Cannot accept orders.
⏳ PENDING
Docs submitted. Read-only access during review. Can track status & contact support. (Screens 6)
✅ APPROVED
Full access. Accept orders, manage catalog, receive payouts, access analytics.
⚠️ SUSPENDED
Read-only. Cannot accept orders. Can view history & contact support. Auto-review after N days. (Screen 8)
❌ REJECTED
Resubmission allowed. Can fix docs & re-apply. Appeal option available. (Screen 7)
🔐 Cross-Cutting Requirements

Platform-Wide Technical Requirements

🛡️
Role-Based Access Control
Owner / Manager / Staff roles. Each role scoped to permitted screens and actions. Enforced on API and UI layers.
Owner
Manager
Staff
📋
Audit Logs
All write actions logged: who, what, when. Accessible to Owner. Retained 90 days. Exportable. Examples: order status changes, catalog edits, payout requests.
🌐
Localization Ready
All strings externalised via i18n keys. RTL layout support. Currency, date, and number formatting via locale config. Initial: EN, HI, ML, TA.
📶
Offline-Lite Mobile Mode
Service worker caches last-known orders and catalog. Queues status updates locally. Syncs on reconnect. Banner shown when offline.
🔒
Secure Media Upload
All uploads go via signed URLs. File-type & size validation on client and server. Malware scanning before storage. No direct S3 public access.
🔔
Real-time Notifications
WebSocket / SSE channel for new orders, SLA warnings, payout confirmations, and chat messages. Falls back to polling on restricted networks.
